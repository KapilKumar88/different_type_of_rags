# Structured Data RAG Module Plan

## Module Purpose and Scope

Implement uploaded-data Structured Data RAG on top of the existing protected Naive RAG flow. The module supports structured extraction, storage, retrieval, and answer grounding for CSV, XLSX, JSON, Markdown tables, DOCX tables, and PDF tables while preserving existing document-scoped conversations and SSE streaming.

Out of scope:

- External SQL database connectors.
- Credential storage for third-party data sources.
- Raw SQL generated by the LLM.
- Queue-based ingestion.

## Key Technical Decisions

- Structured scope is uploaded data only: CSV, XLSX, JSON, Markdown tables, DOCX tables, and PDF tables.
- PDF tables use the already-installed `pdf-parse` `getTable()` API; borderless or OCR-only tables may fall back to text.
- Structured rows live in Postgres JSONB with typed column metadata; Qdrant stores text chunks and table-summary points, not every row.
- LLM output is limited to validated JSON query plans. The backend executes only a safe internal query-plan DSL, never raw SQL from the model.
- Retrieval remains scoped through authenticated conversations and their selected document IDs.
- Prompt construction keeps retrieved content and structured rows inside explicit untrusted context boundaries.
